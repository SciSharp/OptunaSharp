VolleyEval

a sampler × challenge profile matrix

There is no single best sampler — only a best sampler per regime. VolleyEval fires a volley of optimization challenges at every contender, auto-tunes each one against each challenge, and records where it wins, where it abstains, and where it cannot compete — accumulating, over time, a strength/weakness map no single leaderboard can tell.

The unit per model

Each model rolls up to a figure of merit — a small tuple, not one number

The atomic measurable unit is the normalized score per (model × challenge) — a real number in [0,1] with a fixed zero (random) and one (optimal). Roll a model's row up and you get its per-model figures of merit: mean (robustness), regimes won (a rank-tournament — how often it is best), peak (does it own any regime at all), and coverage (did it even compete, or DNF / abstain). Each also exists per-wall-clock. VolleyEval reports the tuple and refuses to collapse it to one headline scalar — that scalar would hide the regime inversion the whole suite exists to show.

The volley

Twelve challenges — what each column actually probes

The samplers are only half the matrix. Each column is a challenge: a define-by-run objective with a known (or best-seen) optimum, a random baseline that fixes the zero of the score band, a trial budget, and a falsifiable champion hypothesis. They are picked to span difficulty space (the axes table below), so every sampler's strength and weakness is exposed by some column. Each thumbnail is the actual landscape; ● anchored marks challenges with measured cells, ○ hypothesis the rest.

How a ranking is earned

Every cell is a tuned, validated, seed-averaged run

A round is not one training run — it is a nested study. Each challenge gets to hyperoptimize the sampler it faces, so a contender is judged at its own best, never a stale default. The outer study is itself an OptunaSharp study whose objective runs an OptunaSharp study — "optimize the optimizer," realized inside the library.

01

Outer study tunes

TPE searches the contender's declared knob space — NSGA's population_size, crossover_prob…; TPE's n_startup, multivariate, group; CMA's sigma0, popsize, restart.

02

Inner runs the challenge

For each knob set, the sampler drives the challenge to its trial budget on the search seeds and returns the aggregated best-at-budget.

03

Held-out validation

The outer winner is re-run on unseen seeds. Mandatory: a single-seed best of 13140 validated to 12617 — the gap is exactly the seed-overfit this step guards.

→
04

Recipe filed

The validated hyperparameters are written to the recipe library, keyed by (contender, challenge, budget) — a reusable answer, not just a score.

Two metrics, never one quality

A single number hides the trade a researcher actually makes.

  • Best-at-budget — final objective after the fixed trial budget. "How good does it get?"
  • Trials-to-threshold — trials to first reach 50 / 90 / 99% of the optimum-above-random band. "How fast does it get there?"
  • Both reported as a seed distribution — median + IQR — never a bare mean; the 2026-09-10 runs showed a 12277–13140 spread on one config.

Two leaderboards, never one fairness

Per-trial cost spanned 20–800× in a single session — a cost-blind board is useless in practice.

  • Per-trial-budget — pure sample efficiency; every contender gets N trials.
  • Per-wall-clock — practical efficiency; every contender gets T seconds. TPE spent 537 s where QMC spent 24 s for the same 500 trials.
  • DNF and inert are results. BoTorch's 830 s / 11 trials is DNF(infeasible); native CMA on categoricals is ≡random(inert). Both are signal, not a gap.
Why these challenges

The catalog must span difficulty space

Samplers diverge along measurable axes. The challenge set is chosen so that every contender's strength and weakness is exposed by some challenge. A challenge no contender struggles with is worthless and is rejected.
