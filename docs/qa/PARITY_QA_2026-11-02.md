## How this run works

1. Pick the next direction from the queue below and mark it **in progress**.
2. Read the Optuna source for the area, then run Python first and record what it does.
3. Run the same inputs through OptunaSharp (a scratch probe console that references the built Core), diff.
4. Every difference becomes a finding (ID `QA-n`), with severity, a reproduction test and an explanation.
5. New ideas go to the queue; a direction that needs an owner decision is **paused** with its question listed
   under "Questions for the owner".

Severity: **HIGH** = wrong results/crash on a common path; **MEDIUM** = wrong results/messages on a less common
path; **LOW** = cosmetic or exotic-input divergence; **NIT** = message wording only.

Known issues already inventoried in the catalog (`optunasharp/optunasharp.md`, Open items 17–24) are not
re-reported here.
